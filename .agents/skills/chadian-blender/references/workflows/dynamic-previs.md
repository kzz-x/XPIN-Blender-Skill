# Workflow｜动态三维分镜与 Previs

> **Art Direction + Motion Direction First**。静态关键帧决定画面，动态预演决定它是否真有空间感、运动质量和准确节奏。先验证再昂贵制作。

## 设计输入与主动导演

- 从口播/时间码、成熟参考片段、资产、Visual Anchor 出发；用户只给大白话时，主动识别专业镜头语言并寻找对应参考。
- 不照搬二维排版到三维：主动设计前/中/后景、景深、遮挡、视差、尺度变化和空间揭示。
- 联合编排 **Camera（Dolly / Truck / Orbit / Crane / Follow / Reveal）+ Object（展开/重组/错层/变形）+ Focus/Light**。运动必须服务信息点；不是所有元素都同时动。
- **单个镜头**初稿可从「1 条主摄影机运动 + 1 段关键物体运动 + 必要的焦点/灯光变化」开始控制复杂度；**完整段落必须另行设计镜头组接**，不能将单镜头简化原则套用为一镜到底。以高质量动态参考为标准，不因 AI 实现容易而选择平面化镜头。
- 有参考视频时提取**运动意图与节奏**，允许重设 Rig/曲线；不照抄无法维护的实现。

## 镜头组接与剪辑节奏（完整段落必检）

- 先根据口播的**信息层级、强调词、转折与停顿**划分视觉节拍，再决定镜头数量和切点；不平均分配镜头时长，也不为了频繁切镜而切镜。
- 主动评估**全景/中景/近景/特写/微距**的景别变化，以及正侧、低机位、俯视等角度切换；用空间建立→重点揭示→细节强调→关系归纳等镜头功能组织段落，不要求每段用全套景别。
- 每个信息节点都判断**连续运镜还是切镜**：空间关系、结构展开可用连贯运动；尺度跳变、强调对比、观点转折、微距细节往往适合直接切镜。硬切、动作匹配切、遮挡切、匹配构图等转场按表达需要选择。
- 设计**静与动、快与慢、远与近、正与斜**的对比。避免连续匀速推拉、同角度漂移、景别长期不变和没有信息价值的复杂炫技。强调整体速度曲线与必要的停顿/阅读时间。
- 规划镜头衔接的主体位置、视线/运动方向、运动接续、遮挡和焦点；有意制造跳切或突变时，应明确目的。优先让剪辑点落在口播或动作的有效节点。
- 多镜头可分别用 Blender 相机/Shot 管理，再在 Blender、AE 或剪辑软件组接；具体工具不限，**验收对象必须是按实际切点剪好的整段预演视频**，不能只展示独立相机动画。

## 动态分镜交付

完整段落先给简短的 **Shot/Event 表**；单镜头任务可省略多镜头组接部分：

| Shot / 起止时间 / 切点 | 叙事重点 | 景别/机位及运镜或静止 | 主体动作/空间关系 | 焦点、灯光、文字及衔接 |
|---|---|---|---|---|

- 时间与用户提供的口播、字幕、Marker 对齐，明确入场/揭示/信息落点/停顿/出场以及每次切镜的依据；未知的时间必须标「暂定」，不可伪称精确。
- 关键姿态覆盖开头、主要转折和结束，说明摄影机相对主体的空间关系；静态 Anchor 之外，必须评估实际运动和过渡。
- 在 Build 前指出平面化、遮挡、穿模、镜头过快/过慢、焦点漂移、信息来不及阅读等风险。

## 动态 Previs Gate

1. 复用确认过的 Visual Anchor 与资产，构建 Proxy/Blockout；使用**真实摄影机和真实空间位置**，基础材质/灯光即可。
2. 先做**按 Shot 切点组接的完整时长低成本预览视频**，不以静帧或未剪辑的单镜头预览替代；至少检查首、中、尾和转折处的景别/机位变化、运镜与切镜配合、动静快慢、视差、遮挡、转场连续性、节奏和信息可读性。
3. 通过后再细化模型、材质、复杂 FX、最终灯光与渲染；预演锁定的是**创作意图**，质量不达标仍可优化技术路线。
4. 未获认可时优先在 Proxy 和 Rig 阶段迭代，不为每次镜头修改重建昂贵场景。

## 动画必须易于改时间与构图

- 首个主 Key 前确认 Motion Ownership：Camera Rig、Aim Target、Focus Target、Group Rig、Local Motion 各司其职；Camera Path/约束/父子变换与视觉调整分离。
- 用 **IN / REVEAL / FOCUS / SETTLE / OUT** 等语义 Marker 管理事件；对应动作以可调整的时间区间、Progress、Action/NLA 或生成脚本映射到事件时间。**Marker 本身不会自动重定时 Key**，只有建立真正的绑定或重定时流程后才允许宣称「移动 Marker 即同步」。
- 常改的控制项为：镜头距离/环绕幅度/路径形状、主动作进度与强度、开始/结束时机、Stagger、Focus、灯光；少量中文分组控件，底层数据保留在 .blend。
- 允许复杂多段动画，但结构优先于堆 Key；口播节点变动应能修改事件时间或少量主曲线，而非逐个挪动几十个对象的 Key。

**验收：** 完整段落的视频有明确的空间调度、景别/机位变化和有依据的切镜节奏；既没有为了省事而一镜到底，也没有为了刺激而无意义快切。手动修改主运动幅度、目标构图、切点或关键时间，关联对象/镜头能正确响应，原有人工细调得到保护。
