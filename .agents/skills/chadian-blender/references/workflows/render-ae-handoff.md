# Workflow｜渲染预算、质感与 AE 交付

> 目标：在用户约束的总渲染时间内，最大化**实际成片质量**。默认参考目标为 **90 分钟/镜头任务**；若用户指定其他预算，以其为准。时间是待验证的目标，不是未经基准测试的保证。

## Render Budget Gate

1. 获取 GPU/VRAM、Blender 版本、目标分辨率、帧率、时长/帧数、输出通道、渲染设备与场景复杂度；未知值明确标明。
2. 分别对有代表性的低/中/高复杂度帧测试耗时，包含玻璃最多、反射/体积最重、动画极值的帧。
3. **预计总耗时 = 不同复杂度帧的分段平均耗时 × 对应帧数 + 加载/降噪/保存/通道等开销**；保留一定缓冲。不拿单张简单帧的耗时承诺整个序列。
4. 超预算时按「视觉收益/成本」优化后重测：设备/GPU 与显存瓶颈 → 分辨率和样本数/自适应采样/降噪 → 光线反弹与透明/体积 → 阴影、贴图和几何细节 → 必要时更换渲染器或分层。
5. 时间有余量时优先改善主角轮廓、打光、接触阴影、核心材质和时序稳定性，而非盲目增加 Samples。禁止未经授权直接启动高成本全片最终渲染。

## Eevee / Cycles 与玻璃

- **以目标画面和实测选择**：Eevee 往往适合风格化工业展示、线框/HUD、轻量灯光与快预览；Cycles 优先用于关键的多次反射、透射、物理折射、复杂软阴影和写实微距。复杂场景可做 A/B 帧测试或按层选择方案。
- 两者的材质、折射、阴影和屏幕空间效果并不完全一致；**切换渲染器后必须重新检查材质、光影、透明、Pass 与画面质量**，不能仅改引擎开关后直接全片出图。
- 高级玻璃靠厚度、倒角、粗糙度、边缘反射、环境/软箱布光和可信的层次；多层玻璃、焦散、体积散射、深光线路径按镜头贡献酌情启用。主角可保留物理准确性，非重点部分使用可控近似；不牺牲参考图的关键质感。
- 景深、运动模糊、发光/辉光等按最终遮挡与合成要求决定 3D 渲染或 AE 后期，不预设全部烘进 Beauty。

## 建模与资源策略

- **Asset First**：优先官方/可授权成熟模型、材质、HDRI 和现有模板；真实硬件结构必须可信。改造现成模型通常优于从零用代码猜细节。
- 程序化结构/阵列/拆解/碎片 → Blender Python 或 Geometry Nodes；它们本身就是代码建模。生成独立 GLB/mesh 文件只在交换、特定算法或轻量几何有实际优势时使用。
- 以**最终可编辑程度、质量、迭代次数与 Agent 调用成本**判断路线，不以「代码生成」标签预设 token 更省。

## Blender → AE / AE → Blender

- AE 擅长可改文字、字幕、HUD、表格、信息图；真实三维投影、遮挡、折射交互、厚度文字更适合 Blender，或提供单独的遮挡/阴影通道。
- 摄影机/Null/Empty/对象的变换、动画时间及部分镜头参数可经工具或数据格式交换；**不保证 AE 表达式、F-Curve、材质、灯光、复杂模拟和全部镜头属性无损往返**。必要时逐帧采样相机变换以保留可见轨迹，Blender 内仍保留可编辑主 Rig。
- 交接验证分辨率/画幅比例、FPS、首帧偏移、单位/坐标轴/方向、焦距/视角、相机父子变换、景深目标与画面叠合；抽取多帧 Overlay 核对。
- 精确互通属于单独测试事项：按已安装插件/脚本能力选择 AE ↔ Blender 路线，不声称任何插件天然「完美无损」。

## 合成 Pass 与交付

- 先按 AE 修改需求规划 View Layer / Pass：Beauty（Combined）、Alpha、对象或材质遮罩、Shadow、Emission、Z-Depth、需要时 Cryptomatte/Normals/Motion Vector；仅输出用得上的通道。
- 高质量母版优先 **多层 OpenEXR 序列**（注意位深、线性色彩/OCIO/显示变换与 AE 解码）；兼容性需要时另出透明图像序列/单独蒙版。
- Eevee/Cycles 的 Pass 能力、AE 端 Cryptomatte 支持和插件读取效果需要实测；不能把 Pass 列表等同于每种引擎/AE 配置都可直接使用。
- 交付 .blend、预览视频、主渲染序列/Pass、AE 对齐信息（FPS、分辨率、相机版本、起始帧、色彩管理）、依赖清单。先验证一个代表帧在 AE 内对齐，再批量输出。

**验收：** 预算有实测依据；关键材质不因优化明显失真；时间序列无显著噪点闪烁、错误遮挡/阴影；.blend 可继续手调，AE 可正确复合所需通道。
